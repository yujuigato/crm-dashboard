Background

這個工具在解決什麼問題？

業務主管需要頻繁查詢 CRM 資料（客戶清單、跟進狀態、業務分佈），但每次都要請工程師幫忙寫 SQL，等待耗時且無法即時回應業務需求。

😣 過去的痛點

  • 每次查詢需要請工程師寫 SQL，回應時間以天計算
  • 主管無法即時依業務情境調整查詢條件
  • 查詢結果以 email 傳送，格式不統一、版本混亂
  • 報表匯出需要工程師介入，主管無法自主掌控

✅ 工具如何解決

  • Streamlit GUI 介面，業務拉選單即可多條件組合查詢
  • 直連 SQL Server，查詢即時回傳（秒級）
  • 結果一鍵匯出 CSV 或 Excel，格式固定統一
  • Windows 服務，電腦開機即可在瀏覽器存取，無需啟動任何程式

為什麼選 Streamlit，而不是 Power BI 或 Excel？

Power BI 需授權費用且部署複雜；Excel 連線 SQL 需要設定繁瑣、IT 審核周期長。Streamlit 以 Python 開發，2 小時內從零完成部署，內網環境直接啟動，無需任何額外授權或 IT 申請流程。

1

業務打開瀏覽器

Streamlit 以 Windows 服務方式運行，電腦開機後在內網瀏覽器直接輸入 IP 即可存取，不需要啟動任何程式。

NSSM（Non-Sucking Service Manager）將 Streamlit 包裝成 Windows 服務，開機自動啟動
2

拉選單組合條件

多維度篩選器：業務員姓名、客戶地區、跟進狀態、日期範圍、業務階段等，可任意組合，不限制條件數量。

3

Python 動態生成 SQL

後端依使用者選擇動態組合 SQL WHERE 子句，使用參數化查詢避免 SQL Injection，直連 SQL Server 執行。

每次查詢都是即時連線，確保資料為最新狀態，無快取造成的資料延遲
4

即時回傳 + 匯出

結果以 Streamlit Table 即時顯示，含分頁、排序功能。一鍵匯出 CSV 或 Excel，直接作為業務報表使用。

Engineering Challenges

解決了哪些技術難題？

Challenge 1

SQL Injection 安全防護

使用者選單的值直接拼接進 SQL 字串，是 SQL Injection 的高風險點，尤其在內網環境容易被忽略。

↓ 解決方案

全程使用 parameterized query（佔位符 + params tuple），禁止字串拼接，SQL 結構固定、參數值由驅動層傳入

Challenge 2

Windows 開機自動啟動

Streamlit 是 Python 程序，無法直接設為 Windows 服務；排程任務在使用者未登入時無法執行。

↓ 解決方案

NSSM 將 Python Streamlit 包裝成系統服務，以 SYSTEM 帳戶執行，開機後不需要使用者登入即可在背景持續運行

Challenge 3

動態 SQL 條件組合

使用者可能勾選任意組合的篩選條件（0 到 N 個），固定 SQL 無法應對，但完全動態生成又難以維護。

↓ 解決方案

條件清單動態累積，僅在使用者實際選擇值時加入 WHERE 子句；固定骨架 SQL + 動態條件拼接，確保結構安全

Challenge 4

大量資料的響應速度

CRM 資料量大，若每次操作都全量撈取再前端篩選，響應速度無法接受，使用者體驗差。

↓ 解決方案

篩選邏輯在 SQL 層完成（資料庫端過濾），只回傳符合條件的結果集；Streamlit cache 對不常變動的選單資料進行快取
